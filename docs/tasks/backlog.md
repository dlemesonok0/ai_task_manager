# Backlog

Этот файл хранит продуктовые и инженерные задачи, которые пока не готовы к немедленной реализации или имеют более низкий приоритет, чем задачи из `docs/tasks/current.md`.

## P1

### AI-парсинг задач

Цель: превращать естественный язык в структурированные задачи.

Критерии приемки:
- Backend принимает свободный текст и возвращает название, срок, длительность и приоритет.
- Frontend позволяет создать задачу из результата парсинга.
- Неоднозначные даты или отсутствующая длительность обрабатываются явно.

### AI-декомпозиция задач

Цель: разбивать крупные задачи на конкретные подзадачи.

Критерии приемки:
- Backend возвращает список подзадач с примерной длительностью.
- Пользователь может создать выбранные подзадачи из UI.
- Исходная задача не перезаписывается без подтверждения.

### Ежедневный ритуал планирования

Цель: провести пользователя через планирование и закрытие дня.

Критерии приемки:
- Утренний экран предлагает реалистичный план.
- Вечерний экран показывает выполненные, пропущенные и перенесенные задачи.
- Незавершенные задачи можно перенести вперед.

### Dashboard состояния синхронизации

Цель: сделать проблемы интеграций видимыми и понятными.

Критерии приемки:
- UI показывает время последней синхронизации по каждой интеграции.
- UI показывает последнюю ошибку синхронизации, если она есть.
- Пользователь может вручную запустить обновление или переподключение.

### Google OAuth Flow

Цель: заменить ручную настройку Google token JSON.

Критерии приемки:
- Пользователь может подключить Google Calendar из UI.
- Backend безопасно хранит токены.
- Истекшие токены можно обновить или переподключить.

## P2

### Модель workspace

Цель: подготовить архитектуру к командному использованию.

Критерии приемки:
- Пользователь принадлежит как минимум к одному workspace.
- Существующие персональные данные связаны с workspace по умолчанию.
- API-границы готовы к будущим проверкам ролей.

### Заготовки для billing

Цель: подготовить feature gating для SaaS-тарифов.

Критерии приемки:
- Есть тарифы free, pro и team.
- Проверки возможностей могут ограничивать premium-функции.
- Реальный платежный провайдер пока не требуется.

### Аналитика

Цель: показывать пользователю ценность продукта и прогресс.

Критерии приемки:
- Отслеживаются запланированные и выполненные задачи.
- Отслеживаются focus time и нагрузка встречами.
- Отслеживаются принятые и отклоненные предложения auto-schedule.

### Экспорт данных и удаление аккаунта

Цель: добавить контроль пользователя над своими данными.

Критерии приемки:
- Пользователь может выгрузить свои данные в JSON.
- Пользователь может удалить аккаунт и связанные данные интеграций.
- Поведение удаления покрыто тестами.
