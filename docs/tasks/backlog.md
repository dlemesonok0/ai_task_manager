# Backlog

Этот файл хранит задачи, которые пока не готовы к реализации или имеют более низкий приоритет, чем задачи из `current.md`.

Задачи в `current.md` имеют приоритет при выборе следующей работы.

## Правила

- Перед переносом задачи из backlog в `current.md` проверить, не устарели ли критерии приемки и зависимости.
- Задачам в `current.md` присваивается TASK-NNN идентификатор.
- После завершения задача переносится в `done.md`.
- Статусы: `todo` / `blocked` / `review`.

## Легенда

- **Приоритет** — P0/P1/P2 из roadmap.
- **Эпик** — группа задач (FE / INT / PLAN / AI / OPS / SAAS / UX).
- **Сложность** — S / M / L / XL.
- **Статус** — `todo` / `blocked` (с причиной).

## Эпик OPS: Надёжность и эксплуатация

### TASK-065: Поток для быстрого локального запуска

Приоритет: P1 | Сложность: M | Статус: `todo`

Цель: создать оптимизированный workflow для быстрой локальной разработки без пересборки контейнеров при каждом изменении.

Объем работ:
- Документировать команды для запуска backend и frontend напрямую (без Docker)
- Настроить автоматическую перезагрузку при изменении кода
- Обеспечить работу с локальной PostgreSQL (можно запустить отдельно через docker compose)
- Создать скрипты/алиасы для часто используемых операций разработки

Основные файлы:
- `docs/dev-workflow.md` (новый файл с инструкциями)
- Возможно: обновление `.env.example` с настройками для локальной разработки
- Возможно: добавление Makefile или скриптов для упрощения команд

Зависимости:
- Можно выполнять независимо, но идеally после настройки базовой разработки

- Тесты запускаются быстро, используя in-memory зависимости
- Описан workflow в документе, доступном для новых участников команды
